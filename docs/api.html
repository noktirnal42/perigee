API & safety model

Everything Perigee does is a documented gRPC call to your own hardware. This page explains the shape of that API and the guard rails around it.

Architecture

└───────────────┬───────────────────────────────┘

The protocol stubs are generated from the devices' own server-reflection output (reference/*.protoset) with Scripts/generate-protos.sh. Router and dish have slightly different schemas, so they live in separate modules (RouterAPI, DishAPI).

The local API

Both devices expose SpaceX.API.Device.Device/Handle, a unary call taking a Request (a oneof with ~100 methods) and returning a Response. Perigee uses a small, read-mostly subset:

AreaMethods
Router readsget_status · wifi_get_clients · wifi_get_config · get_radio_stats · get_history · wifi_get_client_history · get_speedtest_status
Dish readsget_status · dish_get_config · dish_get_obstruction_map · get_history
Writeswifi_set_config · wifi_set_client_given_name · dish_set_config
Destructivereboot · dish_stow (slide-to-confirm)

Safety model

Every request passes through GuardedTransport, which classifies the method by name:

ClassRule
read / probeAlways allowed.
writeOnly when “Enable writes” is on (off at every launch).
destructiveWrites on and inside a completed slide-to-confirm (a task-local token).
forbiddenNever sent: authenticate, signed_request, sensitive_request, initiate_remote_ssh, every *factory_reset, *test_mode, debug, firmware/unlock and more. Anything not explicitly listed is forbidden.

Wi-Fi passwords are never held in view-model state, are masked until you authenticate, and are never logged. The exported report omits them and masks MAC addresses.

Write protocol

The router accepts a partial WifiConfig and only changes fields whose matching apply_<field> boolean is set. Perigee's WifiSetting.makeConfig therefore builds a config containing exactly one field and its flag:

WifiSetting.channel(.ghz5, 149)  →  WifiConfig {
    channel_5ghz: 149
    apply_channel_5ghz: true
}

Proto3 omits default values, so channel 0 (“auto”) is expressed by the flag alone. After sending, the service re-reads the config (retrying while Wi-Fi restarts) and only reports verified when the router returns the new value. If the value changed since you reviewed it, the write is refused.

What the router denies over the LAN

CallResult
wifi_get_channelsPermissionDenied
wifi_get_ping_metricsPermissionDenied
wifi_get_traceroute_statusPermissionDenied
dish get_location“Disabled due to policy”

Perigee probes capabilities at connect time and shows them under Diagnose → What this connection allows. A denial doesn't tell us what credentials would unlock it, so the app doesn't claim to know.

Testing

The kit ships 40+ tests: single-field/flag construction for every setting, revert and stale-value logic against an in-memory mock router, the safety gate (including every forbidden method), fixture decoding, stall analysis, and SGP4 against Vallado's reference vectors. No test ever talks to real hardware. perigee-probe is a read-only CLI that decodes every read endpoint from a live router and proves the write gate is closed.

cd Packages/StarlinkKit && swift test
swift run perigee-probe          # read-only live check
swift run perigee-probe ping     # 30 s ICMP stall test

Satellite maths

Orbital elements (TLEs) for the Starlink group come from CelesTrak and are cached. Positions use a near-earth SGP4 propagator (WGS-72), rotated to Earth-fixed coordinates by GMST, then converted to azimuth/elevation for your location. The dish reports its boresight azimuth and elevation; the satellite with the smallest angular separation is shown as the likely connection, with confidence high (< 1.5°), medium (< 4°) or low.

Perigee is an unofficial companion, not affiliated with SpaceX or Starlink. Do not use it on equipment you don't own.
